# 노치 상태 표시

카메라 하우징(노치)이 있는 화면에서 자세가 흐트러졌을 때 사용자가 선택한 노치 왼쪽·오른쪽 또는 모두에 검은 경고 배지를 띄운다.
메뉴 막대 아이콘이 모든 상태를 조용히 전달한다면, 노치 배지는 지금 고쳐야 할 자세 하나만 눈에 띄게 알린다.

## 표시 규칙

| 상태 | 노치 |
|---|---|
| 주의 | 검은 배지 안에 노란 경고 아이콘 |
| 정상 | 표시하지 않음 |
| 보정 중, 판정 대기·불가, 중지, 카메라 확인 필요, 보정 필요 | 표시하지 않음 |

정상 자세에서 아무것도 띄우지 않는 것은 의도한 동작이다.
바르게 앉아 있는 동안에는 노치가 평소와 같아야 하고, 흐트러졌을 때만 시선을 끌어야 하기 때문이다.
운영 상태(중지, 카메라 확인 필요 등)는 메뉴 막대 아이콘과 팝오버가 이미 전달하므로 노치에 섞지 않는다.

## 사용자 설정

팝오버의 **설정** 카드에서 **노치 알림**을 `없음`, `왼쪽`, `오른쪽`, `모두` 중 하나로 고른다. 기본값은 `없음`이다. `없음`을 고르면 현재 배지를 즉시 숨기지만 자세 판정, 메뉴 막대 아이콘, 배너와 소리는 그대로 유지한다.

연결된 화면 중 40pt 배지를 한쪽 이상에 놓을 수 있는 노치 화면이 하나라도 있을 때만 **노치 알림** 행을 표시한다. 비노치 화면만 있으면 행 자체를 숨기되 저장된 선택은 바꾸지 않는다. 노치 화면을 다시 연결하거나 내장 화면을 열면 행과 이전 선택이 복원된다.

변경은 주의 상태 중에도 즉시 반영되고 앱을 다시 실행해도 유지된다. 위치 선택은 다른 노치 앱과 겹침을 피하기 위한 수동 수단이기도 하다. 2026-08-28 공개 AppKit API 조사에서는 앱끼리 노치 영역을 예약하거나 점유를 조회하는 API를 확인하지 못했으므로 충돌을 자동 감지하지 않는다.

## 모양과 위치

물리 노치의 선택한 방향에 붙어 하나의 노치처럼 보이도록 그린다. 왼쪽과 오른쪽 모양은 수평 대칭이다.

- 배지의 노치 쪽 끝은 노치 안쪽으로 12pt 파고든다. 컷아웃의 둥근 모서리 안쪽에 남는 밝은 틈을 덮기 위한 것이며, 이 구간은 노치에 가려 보이지 않는다.
- 노치 바깥으로 드러나는 폭은 방향마다 40pt다.
- 높이는 선택한 방향의 보조 상단 영역 높이를 그대로 쓴다. 화면 해상도에 따라 달라지므로 상수로 두지 않는다.
- 노치에 이어지는 끝은 각지게 두고, 바깥쪽 끝만 다음과 같이 다듬는다.
  - 화면 맨 위에서 가장 넓고, 아래로 오면서 8pt 반지름의 역곡선으로 좁아진다.
  - 노치 바깥쪽 아래 모서리는 8pt 반지름으로 볼록하게 마무리한다.
- 배경은 불투명한 검정이며 라이트·다크 모드에서 같다.
- 아이콘은 SF Symbol `exclamationmark.triangle.fill`을 16pt 크기, 시스템 노란색으로 놓는다.
  아이콘 높이에서 검게 보이는 구간의 중앙에 맞추므로 좌우 여백이 약 8pt로 같다.

## 나타나고 사라지는 방식

주의 상태로 바뀌면 두 단계를 차례로 재생한다.

1. 노치 안에 접혀 있던 검은 영역이 선택한 방향으로 자라 나온다. 0.42초, 감속.
2. 다 펼쳐진 뒤 경고 아이콘이 커지며 나타난다. 0.20초.

주의 상태에서 벗어나면 반대 순서로 되돌린다.

1. 아이콘이 먼저 사라진다. 0.14초.
2. 검은 영역이 노치 안으로 접혀 들어간 뒤 창을 내린다. 0.36초.

주의 상태가 이어지는 동안에는 배지를 그대로 둔다.
점검이 반복돼 같은 주의 판정이 다시 들어와도 다시 펼치거나 깜빡이지 않으며, 주의 상태에서 벗어날 때에만 접힌다.

등장과 퇴장 모두 한 번만 재생하고 반복하지 않는다.
창의 위치와 크기는 이 과정에서 바뀌지 않으며, 변하는 것은 창 안에 그리는 검은 영역의 외곽선이다.
접히는 도중에 다시 주의로 바뀌면 접기를 멈추고 처음부터 다시 펼친다.

손쉬운 사용에서 **동작 줄이기**를 켜면 등장과 퇴장 모두 애니메이션 없이 즉시 나타나고 사라진다.

## 노치 감지

노치가 없는 맥에서는 표시를 만들지 않고 **노치 알림** 설정 행도 보여 주지 않는다.
macOS가 화면마다 보고하는 두 가지 값으로 판단하며, 기기 모델명이나 화면 크기는 보지 않는다.

- `NSScreen.safeAreaInsets.top` — 구현은 0보다 큰 값을 노치 후보 조건으로 사용한다. 이 값 하나만으로 카메라 하우징을 확정하지 않는다.
- `NSScreen.auxiliaryTopLeftArea` / `auxiliaryTopRightArea` — 노치 좌우의 사용 가능한 영역이며, 하우징이 없으면 `nil`이다.

두 값 중 하나만 어긋나도 표시하지 않는다.
검증 기기에 연결된 비노치 화면은 `safeAreaInsets.top = 0`, 두 보조 영역 모두 `nil`을 보고했고 배지가 만들어지지 않았다.

화면을 여러 대 쓰면 화면마다 따로 판단한다.
노치 알림 설정이 `없음`이 아니고 유효 표시 상태가 `주의`이면, 노치가 있는 내장 화면에는 선택한 방향 중 기하가 유효한 배지를 띄운다. 같은 시각 노치가 없는 외장 화면에는 아무것도 만들지 않는다.
40pt 배지를 한쪽 이상에 놓을 수 있는 노치 화면이 하나라도 연결돼 있으면 설정 행을 표시하고, 모두 사라지면 즉시 숨긴다. 이때 저장된 방향은 유지한다.
노치가 없는 맥에서는 메뉴 막대 아이콘이 모든 상태를 그대로 전달한다.

## 표시하지 않는 조건

상태와 무관하게 다음 경우에는 배지를 만들지 않는다.

- 노치가 없는 화면
- 화면 상단 안전 영역이나 좌우 보조 영역을 읽을 수 없는 화면
- 좌우 보조 영역의 세로 위치가 어긋나거나 좌우 순서가 뒤집힌 화면
- 노치 좌우 영역 사이에 간격이 없는 화면
- 선택한 방향의 보조 영역이 배지 폭보다 좁은 화면
- 노치 폭이 배지가 파고드는 12pt 이하인 화면

기하가 조금이라도 모호하면 잘못된 위치에 그리는 대신 숨긴다.
화면을 여러 대 쓰면 조건을 만족하는 화면마다 선택한 방향 중 그 화면에서 유효한 배지만 만든다.
해상도 변경, 화면 연결·해제처럼 화면 구성이 바뀌면 기존 배지를 모두 지우고 현재 화면으로 다시 만든다.
같은 시점에 **노치 알림** 설정 행의 노출 여부도 다시 계산한다.
이때 표시 중이던 배지는 상태가 바뀐 것이 아니므로 등장 애니메이션 없이 즉시 복원된다.

## 입력과 접근성

- 배지는 클릭을 가로채지 않는다. 배지 위를 눌러도 그 아래의 메뉴 막대나 앱이 입력을 그대로 받는다.
- 앱을 활성화하거나 키보드 초점을 가져가지 않는다.
- 접근성 창 목록에 노출되지 않으므로 보조 기술이 빈 창으로 읽거나 위치를 옮길 수 없다.
- 색을 구분하지 못해도 배지의 유무 자체가 신호이므로 상태를 알 수 있다.

## 메뉴 막대 항목과의 관계

배지는 macOS가 상태 항목에 내주지 않는 노치 바로 옆 공간을 쓴다.
왼쪽은 전면 앱 메뉴, 오른쪽은 상태 항목과 가까워 다른 앱이나 긴 메뉴와 시각적으로 겹칠 수 있다. 이때 위치를 반대쪽으로 바꾸거나 노치 알림을 `없음`으로 바꾼다.
전면 앱의 메뉴가 길어 macOS가 상태 항목 일부를 숨기더라도 노치 배지는 그대로 남는다.

## 실행 모드

노치 표시는 사용자 설정이 `없음`이 아니면 실행 모드와 무관하게 동작한다.
메뉴 막대 모드에서도, `--debug` 창 모드에서도 같은 규칙으로 나타난다.

디버그 모드에서는 카메라와 무관하게 표시 상태를 강제해 선택한 위치의 모양과 애니메이션을 확인할 수 있다. 사용자 노치 알림에서 `없음`을 선택하면 미리보기에서도 표시하지 않는다.
[디버깅](debugging.md#노치-미리보기)에서 사용법을 확인한다.
